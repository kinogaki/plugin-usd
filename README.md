# USD

Universal Scene Description as a format plugin for [Kinogaki Studio](https://github.com/kinogaki): usda, usdc and usdz files read into the standard values of the public [studio-sdk](https://github.com/kinogaki/studio-sdk) and written from them, stages composed, materials kept in every render context they are authored in. Rust with no dependencies beyond the SDK and no OpenUSD code.

The library crate is `kinogaki-usd`; `plugin/` (`kinogaki-plugin-usd`) is the dylib Studio loads, `formats/usd.dylib`. Package `kinogaki.usd`, format `kinogaki.format.usd` (`usd`, `usda`, `usdc`, `usdz`). The format's own model, parser and writer is `src/usd/`, which knows nothing of the SDK but its workers, what bounds a read (the read's budget, and the resolver for the files a file names) and MaterialX's documents (`kinogaki-mtlx`, for the documents layers reference); the format converts between its scene and the standard values at its boundary (`src/read/`, `src/write/`) and nowhere else.

## Import

File ▸ Import (and a File node) reads a file into the project's units: `metersPerUnit` and `upAxis` change the points and every placement's frame, not the placements' scale, so the hierarchy keeps its shape. Items come parents first; a material's binding is resolved as UsdShade resolves it (below, the model):

- **Materials**: every Material prim keyed by its path, in a Material Library at the place of the prim holding it, as a USD Scope of Materials is one (UsdShade puts no rule on where a Material is): a Scope holding Materials alone is the library, its name and place kept; Materials beside other prims (under an Xform, a Scope holding more, Scopes of Materials among them, the root) go into a library named `Materials` there (a library holds Materials, never objects), and those inside what Studio holds as one value (an instance's prototype, a point instancer's prototypes, a mesh) into one beside it, said. Each Material is named by its `kinogaki:name` (else its prim's), double-sided as its `kinogaki:doubleSided` says, else unless a single-sided mesh shows it (a mesh's `doubleSided` is its material's Double Sided), its lengths (glTF PBR's thickness, a transmission depth) moved from the stage's units into the project's as its points are. It keeps the first network it holds of an engine's own (`outputs:kinogaki:surface`, each shader's `info:id` a node type's id), MaterialX's (`outputs:mtlx:surface`, each `info:id` a MaterialX definition; a shader holding inputs its definition lacks is the Kinogaki definition inheriting it that adds them) and USD Preview Surface (`outputs:surface`, its shaders as MaterialX's `UsdPreviewSurface`, `UsdUVTexture`, `UsdPrimvarReader` and `UsdTransform2d` with USD's inputs, `opacityMode` and wraps translated); one holding an engine's keeps the next as its standard form, which Studio takes where that engine isn't installed. Shaders no terminal reaches travel with the kept network. Node graphs and interface inputs are looked through. A MaterialX document a layer references (`@look.mtlx@</MaterialX/Materials>`, as the Open Chess Set's looks do) is read as OpenUSD's UsdMtlx reads it, its materials MaterialX networks there (below, the model). A texture's file is an Image node wired into the input that names it: a usdz's entries embedded as ranges of the file read (never copied), files on disk by their absolute path wherever they are, or read in with **Embed Textures**; its color is `sourceColorSpace` (`sRGB` the interop `srgb_rec709_scene`) or the input's `colorSpace`, read as MaterialX's (`raw`, `none` and `data` are data; a MaterialX image of a float or vector is data whatever it says, as MaterialX converts colors alone; the SDK's `format::materialx::image_color`). Colors convert from the space a value says (linear Rec.709 when it says none) into the working space, the fallback of a primvar reader naming `displayColor` among them (it stands for the mesh's color); what USD types a number is one (USD UV Texture's `scale`, `bias` and `fallback`, which a raw normal map is decoded by). A primvar reader names the attribute it reads (`st` is `uv`, `displayColor` `Cd`).
- **Prims**, each placed where the stage places it (`!resetXformStack!` kept), hidden where invisible: groups; meshes and implicit shapes as polygons (faces repeating a point or of fewer than three corners left out and said; left-handed meshes wound the other way), with their subdivision as Studio's standard setting (below), each primvar an attribute on the domain its interpolation names (`st` is `uv`, `displayColor` `Cd`, `displayOpacity` `Alpha`, `normals` `N`; one of a standard attribute's name takes its whole type, its values converted, so Houdini's single-float `rest` is the f64 rest positions and an `int` `id` 64-bit; points, vectors and normals moved into the project, orientations and placements turned as placements are; text primvars as text; one no attribute can hold, of another width than its standard's say or of another count of values than its elements, left out and said with its prim's path, never failing the read), each face's `material` its GeomSubset's binding over its mesh's (a subset of family `materialBind`, the one UsdShade honours a binding in), GeomSubsets of family `part` as the faces' `part` and the others as groups; curves (linear, Bézier, B-spline, Catmull-Rom, NURBS) with `widths` as `width`, their other primvars as a mesh's are and their binding as their `material`; points with `width`, `id` and their other primvars; cameras (lens and film back in millimetres, from tenths of a stage unit); lights, every intrinsic UsdLux kind its standard light (Rect with its color map, Disk, Sphere with `treatAsPoint`, Cylinder with `treatAsLine`, Distant, DomeLight and DomeLight_1 with its pole axis and image format; an input left unauthored at its UsdLux fallback, a DistantLight's intensity 50,000), LightAPI's inputs (diffuse and specular among them), ShapingAPI on any shape but a distant light or a dome (where it is left out and said), its IES profile a file the light reads, ShadowAPI, and whether the camera sees it (`kinogaki:visibility:camera`, else the proposed `visibility:camera`, Karma's `inputs:karma:light:renderlightgeo`, RenderMan's `primvars:ri:attributes:visibility:camera`, Omniverse's `visibleInPrimaryRay`, Arnold's `primvars:arnold:camera`; none of them: unseen); light filters, PluginLights and LightFilters (renderers' own shaders) left out and said, as are light and shadow links that narrow what a light reaches (an exclude, `includeRoot` off, a membership expression); a light's image or profile its own file, a usdz's packed one embedded; written back as an asset path, a held file packed or written into the layer's textures folder, an Image node's reading as Export resolves it).
- **Instances.** A prototype is one value held once, its geometry gathered (an invisible prim of it, and what is beneath, left out as USD hides them) and the prototypes it shows nested as instances (at most eight deep); an instanceable prim and a point instancer (the instances that show) place it. A point instancer's prototype that is itself an instanceable prim alone (placed where the instancer puts it, shown) is the prototype that prim shows, as Export writes them, so several of them showing one prototype in other materials are one prototype. An instance binding a material the prototype's prims leave unbound, or one `strongerThanDescendants`, names it on the Instance domain; a point instancer's `ids` and `velocities` are its instances' `id` and `v`, and each primvar of one value an instance (`vertex`, `varying`) an attribute of theirs, as a mesh's primvar is (`displayColor` their `Cd`, `pscale` their `pscale`). A prototype's prims are named by its first instance's path (a material inside it keyed by that path), never by a name the reader makes up, so a file OpenUSD flattened, holding its own `Flattened_Prototype_N`, reads as any other.

- **Subdivision.** A mesh's `subdivisionScheme` is its subdivision setting (the SDK's `Subdivision`, Detail attributes): `catmullClark`, `loop`, `bilinear`, and Catmull-Clark where none is authored, as USD's fallback is (the Open Chess Set's pieces author none, and Karma smooths them); `none` is no setting, polygons. The level is `kinogaki:subdivisionLevel`, else Arnold's `primvars:arnold:subdiv_iterations` (or `arnold:subdiv_iterations`), else Omniverse's `refinementLevel` where `refinementEnableOverride` is on, else 2 (Karma and RenderMan render the limit surface and write none); a renderer's attribute read as the level isn't kept as a primvar. `interpolateBoundary`, `faceVaryingLinearInterpolation` and `triangleSubdivisionRule` are its options; crease chains are the edges' `crease` (each chain's sharpness, or each edge's, the highest where chains meet), corners the points' `crease`, holes the faces of `subdivision_hole` (kept, where they were left out before). Read on every mesh, whatever its scheme.

Animation, skins and blend shapes are not read: a file is read at its start time code (D25). Render contexts other than the three, a MaterialX document's looks, PortalLights and GeometryLights are left out and said.

## Export

File ▸ Export writes one layer in the project's units (`metersPerUnit`, `upAxis`): a usda, a usdc, or a usdz holding its textures under `textures/`, named `./textures/…` (the project's embedded files, and files on disk that are pictures a usdz holds by their bytes, PNG, JPEG, OpenEXR or AVIF; any other file an Image node names stays a path, said; a usda or usdc names them as every written document does, the SDK's `format::files::Beside`: a file on disk by its path relative to the layer, an embedded one written into `<stem>_textures/` beside it; a path relative to the layer starts `./` or `../`, file-relative as the usdz specification encourages, never a search path). The default prim is the one group the items are under, else one named after the file. Each Material Library (a materials item) is a Scope at its place, named as the library, its Materials beneath by their names, the bindings naming them there; Export hands every library whole (a whole scene's, and each one a selection's objects show). A group holding only libraries, unplaced, is a Scope too; any other group an Xform. Prims carry model kinds, so other applications see the scene's models (OpenUSD's model hierarchy: only group models hold models, contiguous from the default prim): the default prim an `assembly`, a group a `group`, a prim showing geometry or instances a `component`, each prototype a `component` (a `group` when it holds instances), which its instances take through their reference; a Scope, a light and a camera are no models.

- **Materials: every authored network**, by design, a usdz's too. A network of USD Preview Surface's nodes is written as it is, under `outputs:surface` alone. A MaterialX network goes under `outputs:mtlx:surface`, and an engine's under `outputs:kinogaki:surface` with its standard form under `outputs:mtlx:surface`. A node of Kinogaki's own definitions is written as the MaterialX definition it inherits, its own inputs beside, every one (glTF's texture with its whole sampler as MaterialX's glTF texture holding `minfilter`), so other applications know every shader's `info:id` (`usdchecker --arkit` passes) and Studio reads it back as it was. A material's name and Double Sided are its `customData`'s `kinogaki:name` and `kinogaki:doubleSided`. Beside a MaterialX network or a standard form, a USD Preview Surface is made for other applications: the surface translated as every format translates a material into its own model (the SDK's `MaterialNetwork::translated`: MaterialX's translation graphs, OpenPBR Surface to Standard Surface to USD Preview Surface, and Kinogaki's from glTF PBR and Surface Unlit, folded), each texture left feeding an input carried over as a USD UV Texture of the same file (a texture of Kinogaki's as the MaterialX one it inherits), the arithmetic the translation left between them its scale and bias (found by evaluating that arithmetic with the texture at zero and at one); a normal map into `normal`. What else feeds the surface is left at its value and said. Colors are written in the working space, said by `colorSpace`, USD Preview Surface's in linear Rec.709 (a `displayColor` reader's fallback among them); what USD types a number (USD UV Texture's `scale`, `bias` and `fallback`) as it is.
- **Subdivision as authored**: `subdivisionScheme` the setting's (`none` without one), `custom uniform int kinogaki:subdivisionLevel` beside it, `interpolateBoundary`, `faceVaryingLinearInterpolation` and `triangleSubdivisionRule` where they differ from USD's fallbacks, each creased edge a crease of two points, corners and holes; the standard subdivision attributes are no primvars or GeomSubsets. Normals are written only on meshes that don't subdivide, as the schema wants (a subdivision surface's normals are its shape's).
- **Prims**: polygons as a Mesh with its attributes as primvars (`uv` as `st`, `name` a uniform string, and the rest as read; colors in linear Rec.709, USD's own, which other applications read a primvar in whatever its `colorSpace` says), double-sided as its materials are, its faces' materials as bindings (GeomSubsets of family `materialBind` where they differ, each named after the primitive group holding exactly its faces, which isn't written again, so a file's subsets come back once however many round trips), its `part` as GeomSubsets of family `part`, and its other primitive and point groups as GeomSubsets; curves as BasisCurves or NurbsCurves, one prim for each kind, degree, closing and material, bound to it, a polyline closing on its first point periodic without it; points alone as Points; curves' and points' attributes as primvars, as a mesh's (`width` as `widths`, a point's `id` as `ids`); what the host makes polygons of (a B-rep) meshed; lights (a dome whose pole isn't its own +Y a DomeLight_1; ShapingAPI and, off its fallbacks, ShadowAPI applied; `kinogaki:visibility:camera` always) and cameras. An item's value is its own prim when it is one prim and the item holds no children; else the item is an Xform and the value's prims are beneath it (`Geometry`, `Curves`), named beside its children: a gprim holds no prims (UsdGeom's encapsulation rule).
- **Instances as USD's instancing**, never copies. Each prototype is written once, beneath the default prim's `Prototypes`, a `class` prim, so no traversal draws it in place (OpenUSD's advice in UsdGeomPointInstancer's schema), named after the first instance showing it; whatever shows it references it. One instance (as an instanceable prim imports) is an instanceable prim referencing its prototype. Several (as a point instancer imports, and as Copy to Points makes them) are a PointInstancer whose `Prototypes` scope holds an instanceable prim for each prototype and material its instances show it in; each instance is placed by `positions`, `orientationsf` (and the half-precision `orientations` for readers before OpenUSD 24.05) and `scales`, its `id` among the `ids`, its `v` the `velocities`, and every other attribute a primvar of one value an instance (`vertex`), as a mesh's are written (`Cd` the `displayColor` in linear Rec.709); its `extent` is its prototypes' bounds where the instances place them. Instances a point instancer can't place (a shear) are each an instanceable prim with its own matrix. A value several items show (duplicates sharing one) is a prototype each of their prims is an instance of. An object with children holds its instance or point instancer in a child prim, since an instance's prim holds nothing of its own. An instance's own `material` binds its prim, `strongerThanDescendants` where its prototype binds materials of its own (Studio renders every one of them in it); a `material_map` shows a prototype written in the materials it maps to, once a map. An instance's name and `part` in a point instancer have no place in USD's instancing and are left out, said.

## The model

`src/usd/`: the format's own model, parser and writer.

### Reading

- **Layers** (`usd::sdf`, `usd::text`, `usd::crate_file`, `usd::package`): usda text; usdc crates of versions 0.0 to 0.15; usdz packages (stored, 64-byte aligned, nested), every entry read in place. A layer is recognized by its signature whatever its extension says. Every count a crate gives is charged to the read's budget before anything is allocated for it, a compressed section claims no more than LZ4 can give (255 bytes a byte), a value several fields share is decoded once, and paths are at most 4096 elements deep, written, compared and dropped without recursion.
- **Composition** (`usd::compose`, after Pcp): sublayers with offsets and rates, references, payloads (with load rules), variants (authored, session and fallback selections), inherits, specializes, relocates, variable expressions, and instancing. A stage opens from a path, from a path with its bytes given (read once by the caller, whose buffer a package's entries are views of), or from bytes in memory (an embedded file), which names no file beside it. Every file on disk is reached through the SDK's resolver (`format::files::Named`: the file's folder and below, regular files, within the read's budget), and only a `.usdz` opens as a package. A layer is opened once by its identity, the canonical path the resolver gives, however it is spelled (a link, another case), and a package read once likewise. List ops (references, payloads, API schemas, targets) and their checks, prim orders and relocates are applied by hashing their items, so their work is linear in their items; an arc's map through its layer stack's relocations is made once, charged to the read's budget and shared by every index mapping through it, and a large set of pairs maps a path through an index of its paths. A layer stack holds each layer once (a sublayer met again is already there, stronger), a prim index at most 65,536 nodes (a diamond of references brings its nodes again at each meeting, as in Pcp), arcs and sublayers nest at most as deep as the read's budget allows, and an expression's string is at most 4096 bytes, each variable evaluated once. The read's budget's cancellation stops composing, flattening and reading the scene. A MaterialX document a layer references (`@look.mtlx@`) opens as the layer UsdMtlx makes of it (`usd::mtlx`, `kinogaki-mtlx` reading the document and its includes): its materials at `/MaterialX/Materials/<name>`, every node of the graphs a material reads a Shader beneath it (the graphs flattened into it, where UsdMtlx keeps NodeGraph prims and a material interface), feeding its `outputs:mtlx:surface`; a color, and the file of an image of colors, with the color space the document gives it; a file relative to the document. Its looks are left out and said. Flattened, instances reference prototypes written as `Flattened_Prototype_N`, past the names the stage's root prims take, as `usdcat --flatten` writes them; for a scene, each prototype's prims are written beneath its source instance alone, so every prim is at a path of the stage.
- **The scene** (`usd::scene`): a tree of prims, parents first, each with its local transform, `!resetXformStack!`, visibility and bound material, holding
  - a Mesh with its primvars (the layer's arrays, shared, with interpolation, element size, indices and color space), subdivision tags (the scheme, its options, creases, corners, holes) and the refinement level a renderer's attribute gives, GeomSubsets and their bindings;
  - an implicit shape (Cube, Sphere, Cylinder, Cone, Capsule, Plane) as authored, tessellated on request;
  - BasisCurves (linear, Bézier, B-spline, Catmull-Rom; nonperiodic, periodic, pinned) and NurbsCurves; Points;
  - a UsdGeomCamera; a UsdLux light (Rect and Dome with their images, Disk, Sphere, Cylinder, Distant; DomeLight_1's pole; LightAPI's, ShapingAPI's and ShadowAPI's inputs; Kinogaki's `kinogaki:emission`, `kinogaki:groundColor` and `kinogaki:visibility:camera`, and the renderers' camera visibility), its unauthored inputs at their fallbacks for its kind;
  - a PointInstancer placing prototypes; an instance showing a shared prototype, which the flattening says it is and where the prototype's prims are.

  Values are read at one time code. Purposes `proxy` and `guide` load when asked.
- **Materials** (`usd::shade`): every Material prim as its UsdShade network as authored: its terminal outputs per render context (`outputs:surface` USD Preview Surface, `outputs:mtlx:surface` MaterialX, `outputs:kinogaki:surface` an engine's own nodes), its interface inputs, and its Shader and NodeGraph prims with their `info:*`, inputs, outputs, color spaces and connections. Bindings follow UsdShade's resolution (`ComputeBoundMaterial`): the full purpose's binding where one reaches a prim, else the all-purpose one; met from the prim up, the first binding wins unless an ancestor's is `strongerThanDescendants`; at one prim a collection-based binding (`material:binding:collection:<name>`) including the prim beats the direct one, the first in property order winning; a GeomSubset's resolves beneath its mesh. A collection's members are UsdCollectionAPI's: `includes` and `excludes` (a collection among them brings its own), expanded to the prims beneath unless `explicitOnly`, the most specific rule winning, `includeRoot` taking in everything; a membership expression is said and left out.
- **Assets**: the files materials and lights name, a package's entries held as its bytes (no copy), files on disk by path, found by whoever reads them.

### Writing

A scene authors as one layer (`defaultPrim`, `upAxis`, `metersPerUnit`; prims of their model kinds, bindings with their strength, the prototypes instances show, each once in the default prim's `Prototypes` class and referenced by instanceable prims, point instancers with their prototypes beneath them, materials) and writes as usda, usdc 0.8, or a usdz carrying under `textures/` its held assets and the pictures on disk it names; a loose layer names its assets as they are, writing none beside it (the format names them through `format::files::Beside`). Layers write as `usdcat` prints and writes them.

## Checks against OpenUSD

`tools/parity.py` runs `kusd` against an OpenUSD v26.08 build's `usdcat` over OpenUSD's own test layers (local only; OpenUSD is an oracle, never a dependency):

| Suite | Agree |
|---|---|
| usda printed as usdcat prints it | 2,018 of 2,056 (2,017 byte for byte); the rest hold attribute splines (31), array edits (4) or strings that are not UTF-8 (2), which are refused, and one path expression not re-anchored |
| usdc printed as usda | 30 of 30, byte for byte |
| usdz root layers printed as usda | 51 of 51, byte for byte |
| usda written as usdc, read back by usdcat | 2,018 of 2,056 (16 that usdcat can't write either) |
| usdc written as usda | 30 of 30 |
| stages flattened (`usdcat --flatten`) | 1,926 of 2,055 (1,925 byte for byte) |
| scenes read and written, read by usdcat | 2,101 of 2,101 written; 174 layers refused (invalid on purpose, or splines and array edits) |

A usdz the format writes of MaterialX and USD Preview Surface materials with packaged textures passes Apple's `usdchecker --arkit` (USD 25.11; `tests/format/materials.rs`'s `hand_run_usdchecker_arkit_passes_materialx_and_preview_surface_usdz`). An engine's own network (`outputs:kinogaki:surface`) fails its shader registry check, which knows no such shader, whether named by `info:id` or by a source type; a usdz keeps it anyway, by design.

## Performance

Release builds on an Apple M4 Max (16 cores), best of 10, through `kusd` with one worker per core (`examples/kusd.rs`); the files are read from disk, the times include it:

| Case | Time |
|---|---:|
| An 837 × 837 quad grid (700,569 faces, faceVarying `st`), usdc 8.4 MB: opened and read as a scene | 5.4 ms |
| The grid as usda (51 MB) | 13.2 ms |
| The grid as usdz with a 100 MB texture (against 5.5 ms without) | 15.2 ms |
| The grid authored and written as a usdz file | 12.0 ms |
| Pixar's Kitchen Set: composed, flattened and read as a scene (2,742 prims) | 67 ms |
| Kitchen Set, instanced (114 prototypes) | 53 ms |

`kusd grid <out> 837 [MB]` writes the grid; `kusd scene-time <file>` and `kusd bench <layer>` time it.

Through the format into the standard values and back (`tests/format/measure.rs`, release, best of 10 on workers a thread a core, load average 14 to 22 from other work), against the plan's budgets:

| Case | Time | Budget |
|---|---:|---:|
| The grid's usdc read into the standard values | 21.4 ms | 40 ms |
| The grid's usda | 32.1 ms | 80 ms |
| The grid's usdz with a 100 MB texture, against without | +6.1 ms | +20 ms |
| The grid written from the standard values as a usdz | 46.9 ms | 60 ms |
| Pixar's Kitchen Set imported (2,742 items) | 149.6 ms | 250 ms |

## Building

The format builds from this repository and the public studio-sdk, checked out side by side as Studio's tree lays them out (`sdk/` and `plugins/usd/`), with the compiler the SDK pins (`sdk/rust-toolchain.toml`):

```sh
git clone https://github.com/kinogaki/studio-sdk sdk
git clone https://github.com/kinogaki/plugin-usd plugins/usd
cd plugins/usd
cargo test
```
